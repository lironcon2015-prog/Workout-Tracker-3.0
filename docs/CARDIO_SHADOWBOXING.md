## 1. העיקרון המנחה

האפליקציה כולה נגזרת מנפח = משקל × חזרות. לאימון אירובי אין נפח, ולכן כל ניסיון
לדחוס אותו למודל הסטים היה מזהם את כל מה שנגזר ממנו — גרפי נפח, התפלגות שרירים,
מפת חום, E1RM, TM. לכן:

> אימון אירובי הוא **סוג אימון נוסף** (`kind: 'cardio'`) שחי באותו ארכיון ובאותו
> מסך סיכום, אבל **בלי `details`** — תורם 0 לכל מדד נפח, ומביא מדדים משלו:
> זמן, סבבים, ומה שהשעון מדד.

מה שזה קונה: לשונית **מדדים** (`buildMetricsPaneHTML`) עוברת כמו שהיא — היא נגזרת
מ-`entry.watch` ומ-`entry.timestamp` בלבד, לא מהסטים. דופק ממוצע/מרבי, אזורי דופק,
קק״ל, התאוששות דקה, מוכנות הבוקר והקשר תזונתי — כולם עובדים ביום הראשון, בלי שורת
קוד חדשה. וזה בדיוק המדד שבו אימון אירובי נמדד.

## 2. מודל הדאטה

### 2.1 התוכנית (`state.workouts` + `state.workoutMeta`)

```js
state.workoutMeta['שדו בוקסינג'] = {
  kind: 'cardio',          // מבדל יחיד. היעדרו = אימון כוח (תאימות לאחור מלאה)
  color: '#5E5CE6', _thumbIdx: 5,
  isHidden: false, availableInDeload: true, isDeloadOnly: false   // כמו כל תוכנית
};
state.workouts['שדו בוקסינג'] = [{
  type: 'cardio',          // פולימורפיזם קיים במערך התוכנית ('cluster' כבר שם)
  rounds: 12, workSec: 180, restSec: 60, prepSec: 10,
  soundPack: 'boxing', duckMusic: false,
  combos: [
    { from: 1, to: 4,  text: 'ג׳ב · ג׳ב · קרוס' },
    { from: 5, to: 8,  text: '1-2 · סליפ · 1-2-3' },
    { from: 9, to: 12, text: 'אפרקאט · הוק · יציאה' }
  ]
}];
```

שני המפתחות כבר מסונכרנים לענן (`KEY_META`, `KEY_DB_WORKOUTS`) — אין מקור דאטה
חדש ואין מפתח storage חדש.

**טווחי קומבינציות:** נורמליזציה בשמירה (מיון לפי `from`, קיטום ל-`rounds`).
סבב שאינו מכוסה בשום טווח → שורת הקומבינציה מוחלפת ב"אחריו — מנוחה 1:00".
חפיפה בין טווחים → הטווח הראשון שמכסה את הסבב מנצח (דטרמיניסטי, בלי שגיאה).

### 2.2 רשומת הארכיון

```js
{
  timestamp, date: 'DD.MM.YY', time, type: 'שדו בוקסינג',
  kind: 'cardio',            // ← חדש
  week: 2,                   // מספר השבוע האמיתי (או 'deload') — כמו אימון כוח
  duration: 48,
  details: {},               // ריק בכוונה → נפח 0
  log: [],
  cardio: {
    roundsPlanned: 12, roundsDone: 12,
    workSec: 180, restSec: 60, prepSec: 10,
    workTotalSec: 2160, restTotalSec: 660,
    soundPack: 'boxing',
    rounds: [{ i: 1, workSec: 180, restSec: 60, skipped: false, combo: 'ג׳ב · ג׳ב · קרוס' }, ...]
  },
  summary: 'GYMPRO ELITE SUMMARY\n...',   // אותה כותרת, שורות סבבים במקום סטים
  note, nutritionalState
}
```

### 2.3 גבולות דאטה (checklist מ-CLAUDE.md)

| כלל | מצב |
|-----|-----|
| תאריכים | `date` ב-DD.MM.YY כמו כל רשומת ארכיון + `timestamp` ms. אין פורמט חדש ואין השוואה חוצה-מקורות |
| מערך בתוך מערך | `cardio.rounds` ו-`combos` = מערכים של **maps** — בדיוק כמו `log` שעובד היום. אסור מערך של מערכים |
| `undefined` | כל שדה חסר נכתב `null`, לא `undefined` |
| 1MB | ~120 בייט לסבב; אימון של 12 סבבים ≈ 1.5KB. לא נדרש chunking נוסף |
| דגל "טופל" | אין מנגנון מיגרציה/פולינג חדש. משיכת השעון היא הקיימת (`startWatchAutoPull`) |
| הודעת כשל | נשענת על ההתראה הקיימת בכשל כתיבה לארכיון (נושאת סיבה) |
| בדיקה ב-`test/` | `test/cardio-archive.test.js` — נפח 0, סינון האנליטיקה, בחירת הקומבינציה לפי סבב, שורות ה-summary. נכשלת על הקוד הישן |

## 3. פלואו הכניסה לאימון

```
ui-week ──selectWeek(2)──► ui-workout-type ──כרטיס "שדו בוקסינג"──► ui-cardio-setup
   (רשימת השבוע: אימוני כוח + אירובי, עם תווית "אירובי")               │ "התחל אימון"
                                                                        ▼
                                                                   ui-cardio (Live)
                                                                        │ סיום
                                                                        ▼
                                                                 ui-summary (וריאנט אירובי)
```

- `renderWorkoutMenu()`: כרטיס `kind:'cardio'` מציג "12 סבבים · 3:00 / 1:00" במקום
  "N תרגילים", ותווית "אירובי" בצבע ה-meta. שאר הסינונים (`isHidden`,
  `isDeloadOnly`, `availableInDeload`) חלים עליו בלי שינוי.
- `selectWorkout(key)`: מסתעף לפי `meta.kind` — `'cardio'` → `startCardio(key)`
  (מסך ההיכון), אחרת `checkFlow()` כמו היום. `checkFlow` מקבל גם guard על
  `item.type === 'cardio'` כדי שלא ייתקל בפריט שאינו תרגיל.
- `ui-cardio-setup` ו-`ui-cardio` נכנסים ל-`WORKOUT_SCREENS`; `ui-cardio` גם
  ל-`NO_BACK_SCREENS` (חזרה באמצע אימון = נטישה שקטה).
- `restoreSession()` מחזיר גם אותם — ראה §5.3.

## 4. מסך ה-Live — הלב

- **טבעת אחת גדולה** (אותה גאומטריה של טיימר ה-Live: `r=46`, היקף 289) עם הזמן
  שנותר בספרות ענק, ומתחתיה מילת המצב: `היכון` / `עבודה` / `מנוחה`.
- **צבע = מצב**, לפי הסמנטיקה הקיימת: עבודה `--accent`, מנוחה `--success`,
  היכון `--warn`. אין אדום — אדום באפליקציה הזו הוא שגיאה, לא מאמץ.
- **מסילת סבבים** למעלה: מקטע לכל סבב, מלאים/נוכחי/ריקים — כמה נשאר, במבט.
- **קומבינציית הסבב** מתחת לטבעת. בזמן מנוחה מוצגת הקומבינציה של הסבב **הבא** —
  המנוחה היא הזמן שבו קוראים אותה.
- תחתית: `השהה` (pill), ושתי פעולות טקסט — `דלג לסבב הבא` / `סיים אימון`.
  ללא אייקונים, לפי כלל הפרויקט.
- Wake Lock דלוק כל האימון (`_acquireWakeLock` הקיים), haptic בכל מעבר פאזה.
- **דיוק זמן:** כל פאזה שומרת `phaseEndsAt` מוחלט (`Date.now() + ms`), והטיק מחשב
  מההפרש — לא מונה tick-ים. אותה גישה של `resetAndStartTimer`; בלעדיה האימון סוטה
  בשניות לאורך 48 דקות.

## 5. צלילים

מסונתזים ב-WebAudio על `audioContext` הקיים — **אפס קבצי אודיו**: לא נוספים
ל-`FILES_TO_CACHE`, לא תופסים נפח, עובדים אופליין.

| צליל | מתי | סינתזה |
|------|-----|--------|
| גונג יחיד | תחילת סבב | 3 הרמוניות לא-שלמות (≈620/930/1490Hz) + טרנזיינט רעש קצר, דעיכה מעריכית ~1.6ש׳ |
| גונג כפול | סוף סבב | שתי הכאות במרווח 400ms |
| גונג משולש | סוף האימון | שלוש הכאות |
| קלאקר | 10 שניות לסיום פאזה | שלוש הקשות עץ — רעש מסונן קצר (~40ms), הסימן האותנטי של פינת הקרב |
| ספירה 3-2-1 | סוף ה"היכון" | בליפים קצרים גבוהים |

### 5.1 שילוב עם מוזיקה באוזניות

זו נקודת הכשל האמיתית של הפיצ'ר: ב-iOS, דף שמנגן אודיו יכול **לתפוס את ה-audio
session ולעצור את המוזיקה** — ואז האימון מתחיל בדממה מוזיקלית מלאה.

- **`navigator.audioSession.type`** (WebKit, iOS 16.4+) הוא הידית היחידה שיש:
  - `'transient'` — **ברירת המחדל שלנו.** הגונג מתנגן *מעל* המוזיקה, המוזיקה
    מעומעמת (ducking) לרגע הצליל וחוזרת מיד. זו ההתנהגות הנכונה לפעמון קרב.
  - `'ambient'` — מתערבב בלי לעמעם. הגונג עלול להיטמע במוזיקה חזקה.
  - `'transient-solo'` — עוצר את המוזיקה לזמן הצליל ומחזיר אותה. אפשרות למי
    שרוצה שהגונג יהיה חד-משמעי; נחשף כמתג בהגדרת האימון ("עצור מוזיקה בגונג").
  - `'auto'` (ברירת המחדל של הדפדפן) — הדפדפן מחליט, ועל AudioContext שחי לאורך
    זמן הוא עלול להתייחס לדף כנגן מוזיקה ולעצור את המוזיקה. **לכן קובעים את
    ה-type במפורש** ולא נשארים ב-auto.
- **אסור keep-alive אילם.** אוסילטור שקט שרץ כל האימון כדי "להחזיק את ה-context
  ער" הוא בדיוק מה שגורם ל-iOS לראות בדף נגן פעיל ולהרוג את המוזיקה. במקום זאת:
  `audioContext.resume()` נקודתי לפני כל צליל, והמסך דולק (Wake Lock) כך שהדף
  נשאר בחזית ממילא.
- **דפדפן בלי ה-API** (iOS מוקדם, אנדרואיד ותיק): אין שליטה. הצלילים נשארים
  קצרים (מתחת לשנייה וחצי) כדי למזער את ההפרעה, ו-**ההתראה הקיימת חייבת לומר את
  הסיבה**, לא "שגיאת צליל": "הדפדפן הזה לא מאפשר ניגון מעל מוזיקה — הגונג עשוי
  לעצור את הנגן".
- **עוצמה:** הפלט משותף עם המוזיקה (אותו ערוץ מדיה), ולכן הגונג צריך אנרגיה
  ב-600–1500Hz והתקפה חדה כדי לחתוך דרכה. בהגדרות: מחוון "עוצמת הגונג" (gain
  0.3–1.0, ברירת מחדל 0.7).
- **ערוץ גיבוי — רטט.** `haptic()` בכל מעבר פאזה, תמיד, גם כשהצליל דלוק. אם הגונג
  נטמע במוזיקה או שה-session סירב, המעבר עדיין מורגש.

### 5.2 פתיחת ה-AudioContext

הלחיצה על "התחל אימון" היא זו שפותחת את ה-context (חובה ב-iOS — אין ניגון בלי
מחווית משתמש) ומדליקה את `soundEnabled` אם היה כבוי, כי אימון סבבים בלי צליל הוא
חסר משמעות. ההדלקה הזו נשמרת כמו כל שינוי של המתג הקיים.

### 5.3 מגבלת מסך נעול

צליל אמין כשהטלפון בכיס והמסך נעול **אינו בר-השגה ב-PWA** — ה-context נרדם.
ההנחה היא מסך דולק + Wake Lock, בדיוק כמו במצב Live. אם הדף חזר מרקע באמצע
אימון, `restoreSession()` מחשב מ-`phaseEndsAt` איפה האימון נמצא *עכשיו* ומדלג
קדימה על הפאזות שחלפו — ולא ממשיך מפאזה מיושנת.

## 6. ארכיון

- **כרטיס הרשימה:** אותו רכיב, שלושה מדדים אחרים — `סבבים · עבודה · משך` במקום
  `סטים · נפח · משך`. פס הצבע מה-meta כרגיל, תווית המטא "שבוע N • תאריך" כרגיל.
- **כותרת החודש:** "נפח כולל" לא זז (0 מהאימון האירובי); מספר האימונים כן כולל אותו.
- **מסך הפירוט:** שתי לשוניות — `מדדים` / `ביצוע`. "ביצוע" = רשימת סבבים (מספר,
  עבודה, מנוחה, קומבינציה, וסימון סבב שנקטע). ללא לשונית מאמן.
- העתקה: `buildMetricsSummaryText` נשאר מקור אמת אחד — מצורף בדיוק כמו היום.

## 7. סיכום האימון

מבנה זהה למסך הקיים, שתי סטיות:
- שלושת המדדים למעלה: `משך · סבבים · זמן עבודה` (במקום זמן/נפח/סטים).
- **אין סיכום מאמן** לאימון אירובי — אין לשונית "מאמן", אין קריאה ל-AI, אין
  `aiSummary`. ברירת המחדל היא "מדדים".
- שדה ההערה הקיים בתחתית המסך הוא נקודת התיעוד היחידה (החלטה 3).

## 8. אנליטיקה

מסנן אחד בנקודת הכניסה של המסך — `archive.filter(a => a.kind !== 'cardio')` —
שמוציא את האירובי מכל המשטחים הנגזרים מנפח: bento, גרף נפח, דונאט השרירים, מפת
חום, השוואת סוגי אימונים, שיא נפח, ממוצע דקות. מקום אחד, סיכון מינימלי, וכל
המספרים הקיימים נשארים נכונים בדיוק כמו היום.

## 9. ניהול תוכניות ותרגילים

- **מאגר התרגילים לא נוגעים בו.** "שדו בוקסינג" אינו תרגיל: אין לו משקל, חזרות,
  שרירים או תחליפים. הכנסתו ל-`defaultExercises` הייתה גורפת אותו ל-Freestyle,
  ל-`substituteGroups`, ל-`isUnilateral` ולחישובי הנפח.
- **"צור תוכנית"** מקבל בחירת סוג: `כוח` / `אירובי`. בסוג אירובי הטופס מתחלף —
  שם, צבע, תמונה, סבבים, עבודה, מנוחה, היכון, ערכת צליל, ומעלה/מוסתר/דילואוד
  כמו כל תוכנית. תחתיו: רשימת קומבינציות (טווח סבבים + טקסט).
- כרטיס המנהל: "12 סבבים · 3:00 / 1:00" במקום "N תרגילים".

## 10. חיבורים וקובץ מאוחד

- **`_connectionKeys()`** (החלטה 4): נוספים `KEY_CARDIO_PREFS` — ערכת הצליל,
  עוצמת הגונג, מתג "עצור מוזיקה בגונג" וברירות הזמן. הגדרות, לא דאטה.
- **`exportUnifiedData()`** (החלטה 5): מקטע `cardio` — שורה לאימון (תאריך, סוג,
  סבבים, זמן עבודה, זמן מנוחה, דופק ממוצע/מרבי אם יש). מסונן לפי הטווח דרך
  `inRange`/`timestamp` כמו כל מקטע, ומעודכן ב-`readme`, ב-`counts` ובטקסט
  התיאור של `#unified-export-modal`.
