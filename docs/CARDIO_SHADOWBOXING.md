# אפיון — אימון אירובי: שדו בוקסינג

סטטוס: **אפיון, טרם אושר לביצוע** · מוקאפ: ראה Artifact בשיחה (5 מסכים)
גרסת יעד: 19.13.0 (פיצ'ר משמעותי → עליית minor)

---

## 1. העיקרון המנחה

האפליקציה כולה בנויה סביב **נפח = משקל × חזרות**. לאימון אירובי אין נפח, ולכן
כל ניסיון לדחוס אותו למודל הסטים היה מזהם את כל מה שנגזר ממנו — גרפי נפח,
התפלגות שרירים, מפת חום, E1RM, TM. לכן:

> אימון אירובי הוא **סוג אימון נוסף** (`kind: 'cardio'`) שחי באותו ארכיון ובאותו
> מסך סיכום, אבל **בלי `details`** — כלומר תורם 0 לכל מדד נפח, ומביא מדדים משלו:
> זמן, סבבים, ומה שהשעון מדד.

מה שזה קונה: לשונית **מדדים** (`buildMetricsPaneHTML`) עוברת כמו שהיא — היא
נגזרת מ-`entry.watch` / `entry.timestamp` בלבד, ולא מהסטים. דופק ממוצע/מרבי,
אזורי דופק, קק״ל, התאוששות דקה, מוכנות הבוקר והקשר תזונתי — כולם עובדים ביום הראשון,
בלי שורת קוד חדשה. וזה בדיוק המדד שבו אימון אירובי נמדד.

## 2. מודל הדאטה

### 2.1 התוכנית (`state.workouts` + `state.workoutMeta`)

```js
state.workoutMeta['שדו בוקסינג'] = {
  kind: 'cardio',          // מבדל יחיד. היעדרו = אימון כוח (תאימות לאחור מלאה)
  color: '#5E5CE6', _thumbIdx: 5, isHidden: false
};
state.workouts['שדו בוקסינג'] = [{
  type: 'cardio',          // פולימורפיזם קיים במערך התוכנית ('cluster' כבר שם)
  rounds: 12, workSec: 180, restSec: 60, prepSec: 10,
  soundPack: 'boxing',
  combos: [{ from: 1, to: 4, text: 'ג׳ב · ג׳ב · קרוס' }, ...]   // אופציונלי
}];
```

שני המפתחות האלה כבר מסונכרנים לענן (`KEY_META`, `KEY_DB_WORKOUTS`) — אין מקור
דאטה חדש ואין מפתח storage חדש.

### 2.2 רשומת הארכיון

```js
{
  timestamp, date: 'DD.MM.YY', time, type: 'שדו בוקסינג',
  kind: 'cardio',            // ← חדש
  week: 'cardio',            // לא שבוע כוח; התווית בארכיון: "אירובי"
  duration: 48,
  details: {},               // ריק בכוונה → נפח 0
  log: [],
  cardio: {
    roundsPlanned: 12, roundsDone: 12,
    workSec: 180, restSec: 60, prepSec: 10,
    workTotalSec: 2160, restTotalSec: 660,
    soundPack: 'boxing',
    rounds: [{ i: 1, workSec: 180, restSec: 60, skipped: false }, ...]
  },
  summary: 'GYMPRO ELITE SUMMARY\n...',   // אותה כותרת, שורות סבבים במקום סטים
  note, nutritionalState
}
```

### 2.3 גבולות דאטה (checklist מ-CLAUDE.md)

| כלל | מצב |
|-----|-----|
| תאריכים | `date` ב-DD.MM.YY כמו כל רשומת ארכיון + `timestamp` ms. אין פורמט חדש ואין השוואה חוצה-מקורות |
| מערך בתוך מערך | `cardio.rounds` = מערך של **maps** — בדיוק כמו `log` שעובד היום. אסור מערך של מערכים |
| `undefined` | כל שדה חסר נכתב `null` (למשל `rpe: null`), לא `undefined` |
| 1MB | ~120 בייט לסבב. אימון של 12 סבבים ≈ 1.5KB. לא נדרש chunking נוסף |
| דגל "טופל" | אין מנגנון מיגרציה/פולינג חדש. משיכת השעון היא הקיימת (`startWatchAutoPull`) |
| הודעת כשל | נשענת על ההתראה הקיימת בכשל כתיבה לארכיון (נושאת סיבה) |
| בדיקה ב-`test/` | `test/cardio-archive.test.js` — נפח 0, סינון האנליטיקה, שורות ה-summary. נכשלת על הקוד הישן |

## 3. פלואו הכניסה לאימון

```
ui-week  ──("אירובי" — סקשן חדש בבית, מתחת ל"בחר תוכנית")──►  ui-cardio-setup
                                                                    │ "התחל אימון"
                                                                    ▼
                                                              ui-cardio  (Live)
                                                                    │ סיום / סבב אחרון
                                                                    ▼
                                                              ui-summary (וריאנט אירובי)
```

**למה לא מתוך בחירת השבוע:** שבוע 1/2/3/דילואוד הם פריודיזציה של כוח (TM, %,
דילואוד). לאימון אירובי אין שבוע, והכנסתו לשם הייתה מכריחה אותו לשקר בשדה `week`
ולזהם את רשימת האימונים של כל שבוע. לכן: כרטיס נפרד בבית, ותוכניות `kind:'cardio'`
מסוננות מרשימות השבוע (אותו מקום שבו כבר מסוננים `isDeloadOnly` / `isHidden`).

שני המסכים החדשים נכנסים ל-`WORKOUT_SCREENS`, ו-`ui-cardio` גם ל-`NO_BACK_SCREENS`
(חזרה באמצע אימון = נטישה שקטה). `restoreSession()` חייב לשחזר אותם כמו כל מסך אימון.

## 4. מסך ה-Live — הלב

- **טבעת אחת גדולה** (אותה גאומטריה של טיימר ה-Live: `r=46`, היקף 289) עם הזמן
  שנותר בספרות ענק, ומתחתיה מילת המצב: `היכון` / `עבודה` / `מנוחה`.
- **צבע = מצב**, לפי הסמנטיקה הקיימת: עבודה `--accent`, מנוחה `--success`,
  היכון `--warn`. אין אדום — אדום באפליקציה הזו הוא שגיאה, לא מאמץ.
- **מסילת סבבים** למעלה: 12 מקטעים, מלאים/נוכחי/ריקים — כמה נשאר, במבט.
- **קומבינציית הסבב** מתחת לטבעת (אם הוגדרה) — זה מה שהופך טיימר לאימון.
  בלעדיה: תצוגת "אחריו — מנוחה 1:00".
- תחתית: `השהה` (pill), ושתי פעולות טקסט — `דלג לסבב הבא` / `סיים אימון`.
  ללא אייקונים, לפי כלל הפרויקט.
- Wake Lock דלוק כל האימון (`_acquireWakeLock` הקיים), haptic בכל מעבר פאזה.
- **דיוק זמן:** כל פאזה שומרת `phaseEndsAt` מוחלט (`Date.now() + ms`), והטיק
  מחשב מההפרש — לא מונה tick-ים. אותה גישה של `resetAndStartTimer`, ובלעדיה
  האימון סוטה בשניות לאורך 48 דקות.

## 5. צלילים

מסונתזים ב-WebAudio על `audioContext` הקיים — **אפס קבצי אודיו**: לא נוספים
ל-`FILES_TO_CACHE`, לא תופסים נפח, עובדים אופליין.

| צליל | מתי | סינתזה |
|------|-----|--------|
| גונג יחיד | תחילת סבב | 3 הרמוניות לא-שלמות (≈620/930/1490Hz) + טרנזיינט רעש קצר, דעיכה מעריכית ~1.6ש׳ |
| גונג כפול | סוף סבב | שתי הכאות במרווח 400ms |
| גונג משולש | סוף האימון | שלוש הכאות |
| קלאקר | 10 שניות לסיום פאזה | שלוש הקשות עץ — רעש מסונן קצר (~40ms), הסימן האותנטי של פינת הקרב |
| ספירה 3-2-1 | סוף ה"היכון" | בליפים קצרים גבוהים |

**iOS — הבעיה האמיתית:** `AudioContext` נפתח רק על מחווית משתמש, ונרדם כשהמסך
נכבה. לכן: (1) הלחיצה על "התחל אימון" היא זו שפותחת אותו (ומדליקה את
`soundEnabled` אם כבוי, כי אימון סבבים בלי צליל הוא חסר משמעות); (2) Wake Lock
לכל האימון. **מגבלה שיש להצהיר עליה:** צליל אמין כשהטלפון בכיס והמסך נעול אינו
בר-השגה ב-PWA — ההנחה היא שהמסך דולק (בדיוק כמו במצב Live).

## 6. ארכיון

- **כרטיס הרשימה:** אותו רכיב, שלושה מדדים אחרים — `סבבים · עבודה · משך`
  במקום `סטים · נפח · משך`. פס הצבע מה-meta כרגיל.
- **תווית המטא:** `week === 'cardio'` → "אירובי" (היום: `'שבוע ' + item.week`).
- **כותרת החודש:** "נפח כולל" לא זז (0 מהאימון האירובי); מספר האימונים כן כולל אותו.
- **מסך הפירוט:** שתי לשוניות — `מדדים` / `ביצוע`. "ביצוע" = רשימת סבבים
  (מספר, עבודה, מנוחה, וסימון סבב שנקטע). ללא לשונית מאמן.
- העתקה: `buildMetricsSummaryText` נשאר מקור אמת אחד — מצורף בדיוק כמו היום.

## 7. סיכום האימון

מבנה זהה למסך הקיים, שתי הסטיות שהמשתמש ביקש:
- שלושת המדדים למעלה: `משך · סבבים · זמן עבודה` (במקום זמן/נפח/סטים).
- **אין סיכום מאמן** לאימון אירובי — אין לשונית "מאמן", אין קריאה ל-AI, אין
  `aiSummary`. ברירת המחדל היא "מדדים".

## 8. אנליטיקה

המסך כולו נגזר מנפח. רשומה אירובית עם נפח 0 הייתה מוסיפה עמודה של 0kg
ב"השוואת סוגי אימונים" ומורידה את "ממוצע דקות" — כלומר מקלקלת נתון קיים בלי
לתרום אחד.

**המלצה:** מסנן אחד בנקודת הכניסה של המסך — `archive.filter(a => a.kind !== 'cardio')` —
שמוציא את האירובי מכל המשטחים הנגזרים מנפח (bento, גרף נפח, דונאט, מפת חום,
השוואת סוגים, שיא נפח). מקום אחד, סיכון מינימלי.

מה שלא נעשה עכשיו (המשתמש כמעט לא משתמש במסך): רצועת "אירובי" נפרדת
(סבבים/זמן עבודה/דופק ממוצע לחודש). נשמר כהצעה לעתיד.

## 9. ניהול תוכניות ותרגילים

- **מאגר התרגילים לא נוגעים בו.** "שדו בוקסינג" אינו תרגיל: אין לו משקל, חזרות,
  שרירים או תחליפים. הכנסתו ל-`defaultExercises` הייתה גורפת אותו ל-Freestyle,
  ל-`substituteGroups`, ל-`isUnilateral` ולחישובי הנפח.
- **"צור תוכנית"** מקבל בחירת סוג: `כוח` / `אירובי`. בסוג אירובי הטופס מתחלף —
  שם, צבע, תמונה, סבבים, עבודה, מנוחה, היכון, ערכת צליל, קומבינציות.
- כרטיס המנהל: "12 סבבים · 3:00 / 1:00" במקום "N תרגילים".

## 11. פתוח להחלטה

1. נקודת הכניסה — סקשן "אירובי" בבית (המומלץ) או בתוך רשימות השבוע.
2. קומבינציות לפי סבב — להיכנס עכשיו, או טיימר טהור בגרסה הראשונה.
3. RPE/הערה לסבב בודד — או רק הערה אחת בסוף (ברירת המחדל המוצעת; לתעד סבב
   באמצע עם כפפות אינו ריאלי).
4. `_connectionKeys()` — להוסיף את העדפת הצליל/ברירות זמן? (חובת שאלה)
5. קובץ מאוחד (`exportUnifiedData`) — להוסיף מקטע אירובי? (חובת שאלה)
6. אנליטיקה — סינון בלבד (המומלץ), או רצועת אירובי כבר עכשיו.
