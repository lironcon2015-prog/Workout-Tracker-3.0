# מתכון — Health Auto Export בתזמון דטרמיניסטי (Shortcuts)

מטרה: שנתוני השינה וההתאוששות של הלילה יגיעו לגשר **ברגע שאתה קם**, בלי להמתין
ובלי דחיפה ידנית — ושהאפליקציה תציג אותם בכניסה הראשונה של הבוקר.

> **זה המתכון המומלץ לשינה/התאוששות.** הוא מחליף את `sleep-shortcut-recipe.md`
> (שסוכם דגימות גלם ונתן מספרים שגויים) ואת המתזמן הפנימי של HAE (שלא רץ בזמן).
> התזונה **אינה** עוברת כאן — מקור האמת הוא יומן המזון המובנה באפליקציה.

---

## למה לא להסתמך על המתזמן של HAE (Sync Interval)

| מגבלה | משמעות |
|--------|---------|
| האוטומציות של HAE רצות על **Background App Refresh** | iOS מחליט מתי הן רצות בפועל — לפי סוללה, שימוש ומשאבים. "כל שעה" אינו הבטחה. |
| **Apple חוסמת קריאת HealthKit כשהמכשיר נעול** | ייצוא לא יכול לרוץ בזמן שאתה ישן. הוא יקרה מתישהו אחרי שתפתח את הטלפון. |
| משימת רקע נהרגת אחרי ~30 שניות / זיכרון חורג | ייצוא של "כל המדדים" נהרג באמצע ולא מגיע ליעד. |

המסקנה: **אין** הגדרה ב-HAE שתגרום לייצוא בשעה מדויקת. הפתרון הוא לתת ל-Shortcuts
להיות המתזמן — HAE חושפת פעולה בשם **Run Automation** שמריצה אוטומציה קיימת שלה
**מיידית**, עם כל ההגדרות שלה (יעד REST API, מדדים, Aggregate).

---

## שלב 1 — האוטומציה בתוך HAE (הגדרה חד-פעמית)

באפליקציית **Health Auto Export** → **Automations** → ➕:

| שדה | ערך |
|------|------|
| **Name** | שם קבוע (למשל `GymPro export`) — הקיצור בוחר אותו לפי שם |
| **Automation Type** | **REST API** |
| **URL** | `https://script.google.com/macros/s/…/exec?token=YOUR_SECRET_TOKEN` |
| **Data Type** | **Health Metrics** |
| **Export Format** | **JSON** |
| **Export Version** | **v2** (נתמך; ראה "סכמת v2" למטה) |
| **Summarize Data** | **דלוק — קריטי** (ראה למטה) |
| **Date Range** | **`Today`** — ובנוסף אוטומציה שנייה עם `Previous 7 Days` (ראה למטה). האפשרויות בפועל: Default / Since Last Sync / Today / Yesterday / Previous 7 Days |
| **Time Grouping** | **Daily** (לא Hourly — ראה למטה) |
| **Batch Requests** | כבוי |
| **Sync Cadence** | אין "כבוי" בגרסאות החדשות — השאר 30 דקות כרשת ביטחון. התזמון האמיתי מגיע מ-Shortcuts |
| **Health Metrics** | **רק חמישה** (ראה למטה) |

### Date Range — למה צריך **שתי** אוטומציות

שני המדדים דורשים חלונות מנוגדים, ואין אפשרות אחת שמכסה את שניהם:

| מדד | לאן חותמת הזמן נופלת | החלון הדרוש |
|------|----------------------|--------------|
| שינה / HRV / דופק / נשימה | **היום** — שורת שינה מיוחסת לפי `sleepEnd` (רגע היקיצה) | `Today` |
| `apple_sleeping_wrist_temperature` | לרוב **הלילה הקודם** — דגימה עם חותמת משלה | טווח אחורה |

**נצפה בפועל, בשני הכיוונים:**
עם `Today` בלבד — 2 מתוך 8 לילות קיבלו טמפרטורה; ייצוא חד-פעמי של `Previous 7 Days`
העלה את הכיסוי ל-6 מתוך 8. אבל `Previous 7 Days` **אינו כולל את היום** (השם מילולי),
ולכן כשהוגדר לבדו — סנכרון הבוקר לא עדכן כלום.

**המסקנה:** אוטומציה ראשית `Today` (הזרימה היומית) + אוטומציה שנייה `Previous 7 Days`
(סחיפה של דגימות שהגיעו באיחור), שתיהן לאותה כתובת גשר. פעם ביום מספיקה לשנייה.

**למה זה בטוח:** הגשר עושה upsert לפי תאריך, ומאז **v19.0** דחיפת `Today` שאין בה
טמפרטורה אינה מוחקת ערך שכבר נקלט. לפני התיקון ההרכבה הזו הייתה הורסת את עצמה —
כל דחיפה יומית הייתה מאפסת את מה שהסחיפה הביאה.

> **Time Grouping:** אם תיבחר Hourly, מדדי ה-qty (RHR/HRV/נשימה) יגיעו כדליים
> שעתיים — הגשר שומר את האחרון לכל תאריך, כלומר תקבל את השעה האחרונה במקום את
> הערך היומי. Daily הוא הנכון.

### המדדים — בדיוק אלה, לא יותר

`sleep_analysis` · `resting_heart_rate` · `heart_rate_variability` ·
`respiratory_rate` · `apple_sleeping_wrist_temperature`

בחירת "הכל" היא סיבה מתועדת לכישלון — payload גדול נהרג ע"י iOS. אלה חמשת
המדדים היחידים שהגשר קורא; כל השאר נזרק ממילא.

### סכמת v2 — הבאג ההיסטורי

ב-**Export Version v2** שורת `sleep_analysis` נראית כך:

```
startDate, endDate, totalSleep, asleep, core, deep, rem,
sleepStart, sleepEnd, inBed, inBedStart, inBedEnd
```

**אין בה שדה `date`.** הגשר הישן עשה `_isoDate(r.date)` והחזיר null — ולכן
**כל שורה נזרקה בשקט**, הייצוא "הצליח" והאפליקציה נשארה ריקה. זה היה הבאג
האמיתי, לא Summarize. כעת שורות שינה מיוחסות לפי `sleepEnd` (רגע היקיצה), עם
נפילה ל-`date`/`endDate`/`startDate`.

### למה Aggregate חייב להיות דלוק

בלי Aggregate, HAE שולחת **דגימות גלם** (`startDate`/`endDate` לכל מקטע שלב).
ל-HealthKit יש כמה מקורות שינה חופפים (היסטוריית צימודי שעונים + iPhone), וסכימת
הגלם נותנת מספרים שגויים — **זו בדיוק הסיבה שעברנו ל-HAE מלכתחילה**. לכן הגשר
**מסרב** לדגימות גלם במקום לסכם אותן, ומחזיר:

```json
{ "ok": false, "error": "HAE_NOT_AGGREGATED", "hint": "הפעל Aggregate …" }
```

### בדיקה ידנית לפני שממשיכים

ב-HAE → האוטומציה → **Manual Export** (בתחתית המסך, "Export Existing Data").
אחר כך:
1. **View Activity Logs** באותו מסך — מראה הצלחה/כישלון לכל ריצה, כולל ריצות רקע.
2. בדפדפן: `…/exec?token=YOUR_SECRET_TOKEN` — אמור להופיע `sleep` עם לילה
   בתאריך של **היום** (תאריך היקיצה, לא של אתמול).

## שלב 2 — הקיצור (`HAE Push`)

אפליקציית **קיצורי דרך** → ➕ קיצור חדש בשם `HAE Push`:

1. חפש **Health Auto Export** → בחר את הפעולה **Run Automation**.
2. בשדה ה-Automation בחר `GymPro Sleep`.
3. זהו. פעולה אחת.

> בהרצה הראשונה iOS יבקש אישור גישה לנתוני בריאות — אשר. זה קורה פעם אחת.

**אימות:** הרץ את `HAE Push` ידנית מתוך אפליקציית קיצורי דרך, ואז פתח את ה-PWA →
Composition → שינה. בראש המסך צריכה להופיע השורה "מסונכרן · עודכן לפני רגע".

## שלב 3 — האוטומציות (שלוש)

קיצורי דרך → לשונית **אוטומציה** → ➕ → **אוטומציה אישית**. בכולן:
פעולה = **הפעל קיצור דרך** → `HAE Push`, ו-**"שאל לפני הפעלה" מכובה** (Run Immediately).

| # | טריגר | תפקיד |
|---|--------|--------|
| 1 | **כיבוי שעון מעורר** (Alarm → Is Stopped) | **הראשית.** רצה ברגע שאתה קם — הטלפון בידך ופתוח, בדיוק התנאי ש-Apple דורשת. |
| 2 | **שעה ביום · 09:00** · יומי | רשת ביטחון ליום שבו לא היה שעון מעורר (סופ"ש). ריצה כפולה = no-op. |
| 3 | **שעה ביום · 12:30** · יומי | **השלמת RHR.** Apple מחשבת `restingHeartRate` כמצרף יומי שמתעדכן רק סביב הצהריים — בבוקר הוא עדיין חסר. |

### למה 12:30 בטוחה ולא מזהמת

`mergeSleepDays` הוא **fill-only** לוויטלים הליליים (HRV/דופק/נשימה): ערך תקין
שכבר נשמר בבוקר **גובר** על משיכה מאוחרת. כלומר ריצת הצהריים יכולה רק **למלא**
מדד שהיה חסר — היא לא תדרוס HRV לילי בערך-ערוּת. (ראה `storage.js`, ההערה
"fill-only לוויטלים ליליים".)

> אם השעון המעורר שלך מגיע מ-Sleep Focus ולא מאזעקה רגילה — הטריגר "כיבוי שעון
> מעורר" עדיין תופס אותו. אם בכל זאת לא, החלף אותו בטריגר **"כשאני מתעורר"**
> (Wake Up) אם הוא זמין אצלך, או פשוט הזז את אוטומציה #2 לשעת היקיצה הרגילה שלך.

## איך הנתונים מגיעים למסך

```
Apple Watch → Apple Health → HAE (Run Automation) → health-nutrition-bridge.gs
                                                              ↓ (JSONP)
                              PWA: בטעינה · בחזרה לפרונט · בכל שעה עגולה · בהקשה על "רענון"
```

ה-PWA **לא רץ ברקע** (מגבלת iOS) — הנתונים ממתינים בגשר ונמשכים בכניסה הבאה.
זה תקין ומכוון.

## תיקון היסטוריה — backfill של דופק מנוחה (v19.7.5)

עד v19.7.4 ה-RHR נשמר בכלל **fill-only**: הערך הראשון שנקלט ליום קפא, ודחיפות
מאוחרות לא עדכנו אותו. אבל אפל **מחשבת מחדש** את "דופק במנוחה" לאורך היום ככל
שמצטברים נתוני מנוחה — ולכן המספר בגימפרו נשאר חלוק על Health לצמיתות (בדרך כלל
1–3 bpm). מ-v19.7.5 הכלל הוא **fresh**: ערך נכנס תקין גובר, ערך חסר לא מוחק.

**כדי לתקן ימים שכבר קפאו** (פעולה חד-פעמית מהטלפון):

1. ודא שבאוטומציה של HAE **Aggregate דלוק** ושכל המדדים מסומנים — דחיפה היסטורית
   נושאת גם שורות שינה, ושורה עם שלבים חלקיים **תדרוס** שלבים קיימים.
2. HAE → האוטומציה → **Manual Export** ("Export Existing Data") → טווח של עד
   **120 יום** (תקרת `MAX_DAYS` בגשר; מעבר לזה נגזם ממילא).
3. פתח את ה-PWA. המשיכה הבאה מושכת את כל הימים מהגשר ומעדכנת גם תאריכים ישנים.

**ה-baseline מתקן את עצמו.** אין baseline שמור בשום מקום — `_recoveryBaseline`
מחשב חציון+MAD על 28 הלילות בכל רינדור מ-`SLEEP_DAILY`. ברגע שהערכים ההיסטוריים
מתוקנים, ה-baseline, ה-deltas והציונים נגזרים מחדש מעצמם.

> **ציפייה מכוילת:** הציון עובד על z-score מול החציון. הטיה **שיטתית** מזיזה גם את
> הערך וגם את ה-baseline — הציונים ההיסטוריים כמעט לא ישתנו. מה שכן משתנה: המספר
> המוחלט מתלכד עם Health, וימים שקפאו על קריאה מוקדמת חריגה מפסיקים לעוות את ה-z.

**HRV ונשימה נשארים fill-only** — הם דגימות שנמדדות גם בערוּת, ודחיפה יומית מזהמת
אותן בערכי-ערוּת. RHR שונה: הוא כבר מדד מסונן ומחושב של אפל.

## ייחוס תאריך הלילה — המלכודת שנפתרה

האפליקציה מייחסת לילה ל**תאריך הבוקר**. שני מצבי כשל, שניהם סגורים:

1. **v2 — אין `date` בכלל** (רק `startDate`/`endDate`). הגשר הישן החזיר null
   וזרק כל שורה **בשקט**. זה היה הבאג בפועל.
2. **v1 — `date` קיים אך שגוי לצרכינו**: הוא היום שבו הלילה **התחיל**. לילה
   שהתחיל ב-23:30 נשמר על **אתמול**.

הגשר מייחס כעת שורות שינה לפי **`sleepEnd`** (רגע היקיצה), ורק בהיעדרו נופל
ל-`date`/`endDate`/`startDate` — נכון לשתי הגרסאות.

## פתרון תקלות

| תופעה | סיבה / פתרון |
|--------|--------------|
| `HAE_NOT_AGGREGATED` | Aggregate כבוי באוטומציה של HAE — הדלק אותו |
| `HAE_NO_USABLE_ROWS` | לא נבחרו מדדי שינה/דופק, או שאין נתונים בטווח שנבחר |
| `BAD_TOKEN` | ה-token ב-URL של HAE ≠ `SECRET_TOKEN` בסקריפט |
| `NO_DATA` | ה-payload הגיע ריק — בדוק ש-Period מכסה יום עם נתונים |
| הייצוא רץ אבל האפליקציה לא משתנה | פתח `…/exec?token=…` בדפדפן: אם הלילה שם — הבעיה בצד ה-PWA (ודא שהגשר **דלוק** בהגדרות); אם אינו שם — הבעיה בצד HAE |
| רוצה לדעת אם ריצת רקע הצליחה | HAE → האוטומציה → **View Activity Logs** — רישום הצלחה/כישלון לכל ריצה |
| RHR/HRV נראים כמו ערך של שעה בודדת | Time Grouping = Hourly — העבר ל-Daily |
| הכול נראה תקין אך התיקון בסקריפט לא משפיע | Apps Script: **Deploy → New version**. עריכת הקוד לבדה אינה מעדכנת את הפריסה |
| רוצה לראות מה HAE שלחה בפועל | בסקריפט: `DEBUG_RAW = true` → פרוס גרסה חדשה → הרץ → `…/exec?token=…&raw=1`. **כבה אחרי הבדיקה** |
| שינה 0 / שלבים חסרים | השעון לא נענד בלילה, או ש-`sleep_analysis` לא נבחר באוטומציה |
| ערכים לא תואמים לאפליקציית Health | Aggregate כבוי (סכימת גלם ממקורות כפולים) — ראה למעלה |
