# אפליקציית תזונה ושקילה עצמאית — לבן משפחה

> **סטטוס: ⏸️ מושהה (2026-10-10)** — שלב תכנון בלבד, טרם נכתב קוד וטרם נוצר ריפו.
> בחזרה לפרויקט: קרא מסמך זה, ענה על "שאלות פתוחות", ואז הכן roadmap מפורט (שלבים/קבצים/סיכונים).

## הרעיון
אפליקציה סטנד-אלון למעקב **תזונה + שקילה**, שנגזרת מהיכולות הקיימות ב-GymPro (יומן מזון, שקילות, יעדים, TDEE).
- **המשתמש:** בן משפחה — **לא** בעל GymPro. GymPro ממשיכה כרגיל ולא משתנה.
- **AI-ready אבל עובדת מלא בלעדיו** — סוכן AI יתחבר בעתיד כתוסף, לא כתלות.
- **שמירה מקומית** + תשתית מוכנה לחיבור Firebase.
- **מחוץ לסקופ:** צילום מסך המשקל (Gemini vision), גשרי MFP/Health, אימונים, מאמן.

## השלכות "לא לשימוש שלי"
- אין מיגרציה מ-GymPro — מתחילים מאפס.
- אין בעיית שני כותבים / מקור אמת כפול.
- פרויקט Firebase **נפרד** (לא משותף עם דאטת GymPro).

## ארכיטקטורה מוצעת
**ריפו נפרד, PWA עצמאית** (SW וגרסאות משלה). לא מעתיקים קבצים כמו שהם — `food-logic.js` צמוד ל-`StorageManager`
(~71 הפניות), ל-`haptic`, ל-Gemini ול-`recomputeNutritionDay`. מחלצים לוגיקה לשכבות נקיות:

1. **Store** — ממשק adapter אחיד: `get / put / delete / query / changesSince`.
   - `LocalAdapter` על **IndexedDB** (לא localStorage — יומן ומאגר מזון גדלים, תקרת ~5MB).
   - `FirestoreAdapter` — שלד מוכן, מחובר בהמשך.
2. **Domain API** — פונקציות טהורות JSON-in/JSON-out עם סכמה מתועדת:
   `addFoodEntry`, `getDaySummary`, `logWeight`, `getTrend`, `computeTDEE`, `setTargets`...
   ה-UI וסוכן עתידי קוראים לאותן פונקציות → חשיפה כ-tools / שרת MCP בלי לגעת בליבה.
3. **UI** — עובד מלא בלי AI: חיפוש OFF, ברקוד (ZBar), מזונות מותאמים/מועדפים/אחרונים, ארוחות, יעדים, גרפים, TDEE.
   סריקת תווית / תיאור ארוחה חופשי (היום Gemini) → יכולות סוכן, מוצגות רק כשמחובר.

### מודל דאטה — מוכן לסנכרון מהיום הראשון
- כל רשומה: `id` יציב, `updatedAt`, מחיקה רכה (tombstone) → מיזוג פר-רשומה ב-Firestore, לא דריסת blob/chunks.
- `schemaVersion` + מנגנון מיגרציות.
- תאריכים: ISO `YYYY-MM-DD` (יום מקומי) + timestamp. **אין `DD.MM.YY` בכלל.**
- Firestore: אין מערך-בתוך-מערך, אין `undefined`, 1MB למסמך (ראה כללי "גבולות דאטה" ב-CLAUDE.md).

## דגשים למשתמש לא-טכני
- **אפס הגדרות** — בלי מפתחות API, גשרים או tokens. פיצ'רי AI מוסתרים עד חיבור סוכן (+ החלטה מי מחזיק/משלם על המפתח).
- **Onboarding קצר:** מין/גיל/גובה/משקל/פעילות/מטרה → יעד קלוריות+מאקרו התחלתי; TDEE מתכייל משקילות בפועל.
- **פשטות קודם לעומק:** מסך בית = "נשאר היום" + הוספה מהירה + שקילה. גרפים במסך משני.
- **גיבוי:** בלי Firebase הדאטה רק בדפדפן — ייצוא/ייבוא קובץ + תזכורת גיבוי מהיום הראשון.
- **iOS:** הדרכת "הוסף למסך הבית" באפליקציה; סיכון מחיקת storage של אתר לא פעיל → עוד סיבה לגיבוי/Firebase.
- **תמיכה מרחוק:** מסך "אודות" עם גרסה + "שלח לי דוח" (מצב אפליקציה, בלי הדאטה).
- **פרטיות ב-Firebase:** Google Auth + rules שכל משתמש רואה רק את שלו.
- **בדיקות:** שכבת Domain טהורה → בדיקות Node מהיום הראשון.
